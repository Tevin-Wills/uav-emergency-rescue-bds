1 · Problem & Motivation

In disaster zones terrestrial networks (GSM/LoRa) fail and satellite messengers (Iridium, COSPAS-SARSAT) carry no custom payload. BeiDou Short Message Communication (BDS-SMC / RDSS) needs no ground infrastructure and supports a 210-bit user payload — but its use as a structured rescue-telemetry link for UAVs is uncharacterised.

This node answers one question: can a complete six-field rescue payload fit a single BDS-3 short message and travel reliably, end-to-end, into a UAV mission pipeline?

3 · Methods — Hardware & Encoding

  • Platform: ESP32-D0WD-V3 dev board driving a BDS-3 RDSS module (EVBKIT_V3) with on-board patch antenna, via an RS232–TTL adapter.
  • Frame: $CCTXM,<destID>,<content>*<cs> (NMEA-style XOR checksum).
  • 112-bit payload packs six fields (>iihHBB): lat / lon (int32, 7 dp ≈ 1 cm), altitude (int16 m), uncertainty R (uint16 cm), priority, survivor ID.
  • Timing: firmware tags T1 (send), T2 (module ack), T3 (delivery) for per-message latency.

4 · Methods — Measurement & GCS

  • Field protocol: 4 environments (open sky, light canopy, urban canyon, indoor) × 3 locations × repeated TX; serial logger writes every frame to CSV.
  • Analysis (Python): chi-square test of delivery homogeneity and Wilson 95% confidence intervals (SciPy); bit-accounting for encoding gaps.
  • Ground station (GCS): portal reader → decoder (BIN/ASCII/text) → Leaflet map + QGC WPL 110 waypoint → ROS 2 EmergencyCoordinate on /target/emergency_coordinate.
  • Simulation harness: a virtual BeiDou link (module emulator → virtual portal → live dashboard) reproduces byte-identical frames and Gap-2 latency, verifying the chain without RF.

Encoding (Figs 2–3): binary packing is 57.6% smaller than ASCII for the rescue payload and 69.6% smaller than a full ASCII telemetry string, beating Huffman while carrying more fields. Delivery (Figs 4–5): 100% across all four environments and all 12 sites; χ²=0.000, p=1.000. Latency (Fig 6): every baseline message lands inside the 5 s budget (median ≈ 2.5 s); full diurnal sessions on the 112-bit payload remain to be collected.

6 · Discussion & Limitations

  • Full pipeline is software-complete and verified end-to-end via the simulation harness; frames are byte-identical to firmware output.
  • Position is emulated (lab ground-truth T001–T006), as Objective 5 specifies; live RTK is a separate work item.
  • RF uplink hardware bring-up is unresolved — one TX must confirm the module accepts the 28-char hex payload.
  • Link is one-way; single hardware unit (no generalisability claim); 100% delivery reported as Wilson lower bound.

7 · Conclusion & Future Work

A complete six-field rescue payload fits a single 112-bit BDS-3 short message with 98 bits to spare, delivers at ≥ 93.7% (Wilson LB) with ~2.6 s latency, and drives a UAV mission through a working GCS pipeline.

Next: hardware TX verification · full diurnal latency on the 112-bit payload · live RTK position · group EmergencyCoordinate.msg field extension.
